# 内容对象契约

本文件只定义当前项目中几类内容对象的身份、正式入口、最小内容和不可破坏的边界。两个核心 Skill 为什么存在、怎样与用户互动、何时追问和停止，以 [`Good Idea 两个核心 Skill 产品定义与需求.md`](../Good%20Idea%20两个核心%20Skill%20产品定义与需求.md) 为准；模板只展示 Markdown 形状。

## 共同边界

- **认知归属**：只有用户能够认领闪念卡片和永久卡片。Agent 可以整理候选，不能让候选自动转正。
- **现场与结果分离**：原始思考记录保存发生过什么；候选暴露 Agent 的组织；正式卡片保存用户已经认领的内容。三者不能互相替代。
- **来源与立场分离**：外部材料表示他者说过什么，不自动代表用户赞同、理解或吸收。
- **只保存真实存在的内容**：没有的信息直接省略，不为字段完整而猜测或补写。
- **当前正文优先可读**：文件保存当前可读内容，历史修订由 Git 保留；不在正文中复制完整版本历史。
- **关系必须可解释**：只有确实存在形成关系时才链接，并用自然语言说明为什么有关联。

正式内容和原始思考记录使用 `YYYY-MM-DD-标题.md`。只有同一天出现完全相同的标题时，才增加 `-2`、`-3` 等最小冲突后缀；不增加对象前缀、序号或独立 ID。

## 原始思考记录

原始思考记录保存一次由用户明确发起的捕捉会话或消息线程，回答“当时实际发生了什么”。

- 保存从触发节点开始的全部可见对话、先后顺序和时间。
- 摘要不能替代消息原文；整理后的卡片也不能覆盖原始记录。
- 记录边界由用户明确发起的捕捉决定，不由 Agent 按语义实时拆分。
- 对话中的分支先保存在同一份记录，是否形成多个认知单元留到候选阶段判断。
- 一份记录可以产生零张、一张或多张闪念卡片；零产出不是失败。
- 只有实际形成闪念、永久卡片或外部来源时，才增加 `去向` 并链接对应文件。

正式入口：用户明确要求开始捕捉，或明确要求续接一份既有原始思考记录。

## 闪念候选

闪念候选是 Agent 根据当前表达和共同推理整理出的临时草稿，不是正式内容对象。

- 必须以完整可见内容呈现，让用户能够确认、修改、合并、拆分或拒绝。
- 可以表达对话中新形成的共同理解，不要求逐字复制用户原话。
- 必须与用户原始表达、外部来源和 Agent 推断保持可辨认的区别。
- 未经用户明确认领，不得保存为正式闪念，也不进入默认认知召回。

## 闪念卡片

闪念卡片是用户已经注意到、初步展开并认领，愿意继续辨析其价值的压缩认知结果。它可以是判断、问题、矛盾、直觉、异常观察或新连接，不要求已经完成论证。

最小内容：

- 用户认领的核心内容；
- 为什么当时会注意到它的触发情境；
- 能返回原始思考现场和必要来源的链接。

闪念卡片保留一个 `status`，当前允许值为：

- `待辨析`：已经认领，尚未决定后续去向；新建闪念使用此状态。
- `发酵中`：仍值得保留，但当前缺少继续发展的条件；正文说明缺什么或何时重启。
- `已放弃`：用户明确决定不再发展；历史保留，默认不参与认知召回。
- `已失效`：超过产品定义的认知保鲜窗口且未经辨析，退出默认处理队列；它不表示用户否定了内容，也不删除历史。
- `已形成永久卡片`：已经实际参与形成一张或多张经用户认领的永久卡片。

除产品定义明确规定的保鲜窗口外，时间、相似度或 Agent 判断不能单独改变闪念状态。用户重新认领时，可以把 `发酵中`、`已放弃` 或 `已失效` 的闪念重新置为 `待辨析`。

正式入口：用户认领一个完整可见的闪念候选。

## 永久卡片

永久卡片是用户当前愿意反复调用、接受质疑，并允许未来根据新证据继续修正的阶段性判断。“永久”表示具备长期参与思考的资格，不表示永远正确。

最小内容：

- 脱离原始会话仍能理解的核心判断；
- 用户暂时接受它所必需的理由；
- 确实影响适用范围时才保留的边界或不确定性；
- 实际存在的形成依据。

修订时直接更新当前正文，由 Git 保存旧版。只有判断变化本身有助于理解时，才增加简短的 `演化记录`。用户不再把它作为当前判断时，保留原文并增加自然语言说明，不删除历史。

正式入口：用户认领一个完整可见的永久卡片候选，或认领对既有永久卡片的修订候选。

## 外部来源

外部来源保存带有出处的外部材料，回答“外部世界说过什么”，不表示用户已经形成认识。

- 最少保存标题、原始链接或文件名，以及实际取得的内容。
- 作者、发布日期等信息只有在能够可靠确定时才保存；不能确定时省略。
- 内容缺失、截断或附件未取得且会影响理解时，才说明异常；不记录无助于理解的抓取过程。
- 明显是同一份材料时复用既有记录；无法可靠判断时不猜测合并。

正式入口：用户明确要求保存实际外部材料。

## 有意思

有意思保存用户明确认为值得留下、以后可能继续了解或判断，但尚未认领为闪念、永久卡片，也不要求完整保存来源的内容。

- 至少保存“是什么”；保存动机、链接和情境只在真实存在时保留。
- 它不表示用户已经形成判断，也不等于外部来源的完整快照。
- 只有真实处理结果发生后才增加 `去向`；没有结果时不写“待处理”占位。

正式入口：用户明确表示某个内容有意思、值得留下以后再看，或要求保存为有意思。

## 行动

行动保存用户已经决定在现实中推进或完成的一件具体事情。想法、可选方向、外部材料中的建议和 Agent 推断都不是行动承诺。

- 一份记录只承载一项可以独立推进或完成的行动，至少写清要做什么。
- 对象、完成标准、期限、原因和执行信息只保留用户实际表达过或执行确实需要的部分。
- `status` 允许值为 `待完成`、`已完成`、`已取消`、`已过期`；新建行动默认为 `待完成`。
- 只有实际完成、取消或窗口结束等事件发生后才更新状态，并在需要时记录真实结果。
- 期限不等于已经设置提醒；只有提醒确实创建成功时才能声称存在提醒。

正式入口：用户明确要求把一件事记为行动、待办或任务，或者明确要求改变既有行动。

## 形成依据

形成依据不是独立内容对象。它说明一张闪念或永久卡片实际上由哪些原始思考记录、既有卡片或外部来源共同形成。

形成依据必须用自然语言说明“为什么有关联”，并在原因中附对应文档链接；没有真实关联理由时不添加，不单独维护机械文件清单、独立 ID 或依赖图。
