# 母题：Good Idea

## 母题定义

Good Idea 是一个持续探索个人如何接住、发展、调用和修正认识的项目。

这里的“母题”不是一张永久卡片，也不是一条需要被认领的知识主张，而是一个会长期吸收不同内容的项目域。它保存一个问题域的边界和当前关心的问题，具体内容仍保留在各自的闪念、外部来源、永久卡片、行动和有意思记录中。

## 为什么成为母题

Good Idea 不是一个已经完成的结论，而是一条会从真实使用中逐渐长出来的主线。闪念记录正在形成的认知激活，外部来源保存接触过的材料，永久卡片保存经过辨析、可以独立调用和修订的主张，行动记录项目实际推进的决定，有意思保存尚未进入正式处理但值得保留的线索；它们共同构成这个项目的演化轨迹。

## 当前关心的问题

- 外部输入如何穿过一个人的注意力，进入他正在面对的问题？
- 一次认知激活如何被保存、辨析，并在未来重新参与理解、表达和行动？
- 人与 AI 如何在不丢失认知归属的前提下共同形成判断？
- 一个 Skill 如何从真实运行中逐渐长成稳定的项目结构？
- 如何让内容在被找到、被理解之后，仍然能够在合适的场景中被重新使用？

## 内容集合

母题和内容是多对多关系。一份内容可以属于多个母题，一个母题也可以包含多种内容。当前 Good Idea 母题接收五类内容：闪念、永久卡片、外部来源、行动和有意思。成员关系写在内容文件的 `topics` 字段中，使用稳定 ID `good-idea`；不要把母题归属混入外部来源的 `tags`、永久卡片的场景标签或卡片之间的语义关系。

外部来源的归属不表示赞同其观点；行动保留自身的完成、取消或过期状态；有意思仍只是值得保留的线索。未来增加其他类型时，同样保留各自的身份和状态。

## 归属规则

只有当内容的主体、形成背景或未来去向明显围绕 Good Idea 时，才加入 `good-idea`。偶然提到项目名称不构成归属依据；边界不清时先保留待确认，避免母题集合变成关键词清单。

## 与内容关系的区别

“属于 Good Idea”只说明内容进入了这个项目域，不说明两张卡片之间存在支持、限制、冲突、修正或例证关系。具体关系仍由内容对象自身记录，并且需要有能够解释作用的理由。

## 查询与统计

`topics` 是成员归属的唯一维护位置。上方的内容集合展示由这些字段生成，供直接阅读和点击；不手工编辑生成区域。修改归属或文件路径后，刷新展示：

```bash
python3 工具/查询母题.py good-idea --refresh
```

只查询当前数量、状态和路径时，可以不加 `--refresh`。查询覆盖五类内容，行动等类型包括子目录；原始思考记录继续通过闪念追溯，不单独计为闪念成员。当前展示在执行刷新时更新，没有后台自动刷新。

## 维护协议

母题由 Agent 维护。以后 Agent 新建或修改一份与 Good Idea 相关的闪念、永久卡片、外部来源、行动或有意思记录时，应先保存内容本身，确认保存成功后，再刷新母题展示并读回核验。归属字段和母题展示必须分成两个成功条件：前者保存失败时不刷新，后者刷新失败时不能声称母题已经同步。

如果内容由其他编辑器直接写入，或 Agent 中途异常，可以手动运行同一条刷新命令恢复展示。当前没有常驻文件监听器；对于这个项目，事件发生后由 Agent 立即刷新比等待一个固定周期更及时，定时刷新仍可作为外部写入的兜底。
