# Skill 是 Goodidea 的最小产品形态：以 3.0 为控制层，编排 2.0 与 1.0

## 核心内容

过去对 Goodidea 的理解是：先有一套完整的项目基底，包括规则、结构、数据和能力，Skill 只是其中被调用的一个部件。现在这个关系发生了倒转：Goodidea 在初期不一定先是一个完整项目，它可以先是一个能够交付完整核心体验的 Skill，再让项目从 Skill 的真实运行中逐渐生长出来。

产品做减法，不是把文件和功能减到最少，而是找到**不能继续缩减、却仍然能够形成充分用户体验的最小单位**。对 Goodidea 来说，这个单位可能是一条完整的认知体验闭环：

```text
一个想法出现
→ 被准确接住
→ 被逐步理解
→ 用户仍然拥有解释权和认领权
→ 留下可以继续生长的东西
```

如果一个 Skill 可以独立完成这条闭环，它就不再只是项目的附属功能，而是 Goodidea 最初的产品形态。

### 1. Skill 的本质是三种软件范式的最小编排单元

Skill 可以从外部形态上被理解为“触发条件＋流程＋流程所需的工具”，但更本质的定义是：

> **Skill 是以 Software 3.0 为控制层，把 Software 2.0 的认知能力与 Software 1.0 的确定性能力，组织成完整体验的最小编排单元。**

三种软件范式在 Skill 内部承担不同职责：

```text
Software 3.0
自然语言写成的触发条件、行为规则和流程
        ↓ 调动
Software 2.0
模型权重中已经学习到的理解、判断和生成能力
        ↓ 必要时调用
Software 1.0
代码负责的写入、校验、去重、计时、恢复等确定性动作
```

“用户、模型、程序”是参与协作的不同角色，不是卡帕西所说的三种软件范式。1.0、2.0、3.0 区分的是意图以什么方式被写进软件。用户则位于这三层之外：用户拥有议题的发起权、意义的解释权和结果的认领权。

### 2. Goodidea 的生成路径是“3.0 先行，2.0 赋能，1.0 沉淀”

Skill 权重很高，不等于所有东西都应该写进 Skill。更合理的生产过程是：

```text
先用 3.0 把完整体验跑起来
→ 借助 2.0 处理语义与不确定性
→ 让真实使用暴露脆弱点和重复需求
→ 把已经不能容忍概率性的环节沉淀成 1.0
```

因此，Goodidea 从一个 Skill 长成一个项目，不是在 Skill 外面预先堆叠一套“基底”，而是 Skill 在运行中不断把已经验证的确定性要求结晶成程序、文件、规则和结构。**项目不是 Skill 的预设容器，而是 Skill 运行后留下的稳定沉淀。**

### 3. 1.0 不只负责沉淀，也负责从第一天守住底线

并非所有 1.0 都应该等待试运行后再出现。凡是涉及用户不可让渡的权利，或者失败后难以恢复的要求，都应从第一天成为确定性机制，例如：

- 用户的原始表达必须先被保存；
- 已保存的原文不能被模型静默改写；
- 是否形成正式闪念必须由用户明确认领；
- 写入失败不能被表述成写入成功。

这些不是需要继续探索的体验偏好，而是认知所有权和数据安全的底线。与之相对，怎样倾听、何时追问、如何识别表达结束、怎样形成有价值的回声，仍然是适合先留在 3.0 中、通过真实对话持续修正的问题。

这次试运行本身就给出了一个例子：“这就是我这两天的一些想法”虽然没有直接说“请回应”，但已经完成了当前意义单元的收束。结束识别不应依赖固定触发词，而应由模型判断用户仍在生成，还是已经自然交出了对话空间。这类语义判断应先由 3.0 规定关系、由 2.0 执行理解；只有当某些条件经过反复验证后，才考虑是否把其中的机械部分下沉到 1.0。

由此形成一条可以持续指导架构选择的原则：

> **用 3.0 探索体验，用 2.0 承担认知，用 1.0 守住底线并沉淀确定性。**

以后面对任何新要求，都可以先问：它是仍需探索的体验问题、需要模型处理的认知问题，还是已经不能容忍概率性的确定性问题？答案决定它应该继续留在 Skill、交给模型，还是下沉为程序。

## 触发情境

2026-09-29，在实际测试第一个 Goodidea 捕捉 Skill 时，松海回顾了自己最近的两次认知变化：先是从“Skill 只是项目中的一个部件”转向“项目初期最重要的是先让 Skill 跑起来”；随后又意识到，Skill 的流程不应全部交给大模型，而应让模型与代码分别承担擅长的环节。

讨论进一步借助卡帕西《Software Is Changing (Again)》中的 Software 1.0、2.0、3.0，澄清了 Skill 的位置，并在松海明确确认后形成上述表述。同时，本次测试也暴露出当前 Skill 对自然结束信号判断过于保守，为“哪些行为继续留在 3.0、哪些行为应下沉到 1.0”提供了第一个真实案例。
