# 数据层

数据层只回答“已经保存了什么”，不定义对象应该意味着什么。当前数据层只保留人能够直接阅读和修订的 Markdown 事实。

## 目录

```text
数据/
├── 记录/                 正式 Markdown 内容
│   ├── 有意思/           值得留下、以后再处理的内容
│   ├── 行动/             松海已经决定推进或完成的待办事项
│   ├── 闪念/             松海已经认领的闪念卡片
│   │   └── 原始思考记录/ 闪念生成过程的完整思考记录
│   ├── 永久卡片/         松海当前认领的阶段性判断
│   └── 外部来源/         带有作者、出处等客观信息的外部内容
├── assets/                图片与附件
└── 模板/                 Markdown 事实格式示例
```

### 数据格式边界

对象身份、最小内容、状态语义、转换条件和召回后果统一见 [`../规则/内容对象.md`](../规则/内容对象.md)，不在数据层重新定义。

- 目录和模板只展示当前文件位置与 Markdown 形状，不因此成为产品规则来源。
- 模板中的 frontmatter 是可复制的数据示例；允许值和更新条件仍以对象契约为准。
- 卡片只保存当前可读事实，修订历史由 Git 保留。
- 人不需要运行程序就能理解已经保存的内容。

## 文件命名

- 正式记录统一使用 `YYYY-MM-DD-标题.md`，例如 `2026-09-25-关于职业选择的讨论.md`。
- 只有同一天出现完全相同标题时，才追加最小冲突后缀，如 `YYYY-MM-DD-标题-2.md`。
- 文件名首先服务于阅读和链接；不放对象类型前缀、序号或独立对象 ID。
- Markdown 内部只保存理解内容所需的正文、客观信息和解释性链接。
- 关联写成“为什么有关联”加对应文档链接，不单独列机械依赖或文件清单。
