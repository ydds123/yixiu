# 数据层

数据层只回答“已经保存了什么”，不定义对象应该意味着什么。当前数据层只保留人能够直接阅读和修订的 Markdown 事实。

## 目录

```text
数据/
├── 记录/                 正式 Markdown 内容
│   ├── 有意思/           值得留下、以后再处理的内容
│   ├── 行动/             松海已经决定推进或完成的待办事项
│   ├── 闪念/             松海已经认领的闪念卡片
│   │   └── 原始思考记录/ 闪念生成过程的完整思考记录
│   ├── 永久卡片/         松海认领的阶段性主张及其保留的历史
│   ├── 母题/             长期问题域的集合对象
│   ├── 项目/             具有阶段目标、文章和材料的专题性对象
│   └── 外部来源/         带有作者、出处等客观信息的外部内容
├── assets/                图片与附件
└── 模板/                 外部来源、有意思与行动的格式示例
```

## 维护位置

原始思考记录、闪念与永久卡片的定义、规则和模板，只在所属 Skill 目录内维护：

- [捕捉 Skill](../.codex/skills/goodidea-capture/SKILL.md)：原始思考记录与闪念。
- [辨析 Skill](../.codex/skills/goodidea-distill/SKILL.md)：永久卡片及闪念的后续处理。

本目录保存实际记录，不保留上述定义或模板的副本，也不保留旧模板跳转入口。修改能力时到对应 Skill 目录，修改已经认领的内容时到对应记录文件。

外部来源、有意思与行动的说明暂存于 [其他记录对象说明](../规则/内容对象.md)，格式示例仍在 `数据/模板/`。外部来源的标签配置保存在 [标签清单](../规则/标签清单.json)。

母题是集合层对象，具体定义与维护规则保存在各自的母题文件中；内容通过自身 frontmatter 的 `topics` 字段加入母题，不复制正文。项目是专题性对象，使用独立项目文件夹保存阶段性文章和支撑材料；是否建立项目索引，等出现实际查询或汇总需求时再决定，不把项目材料混入母题目录。当前 Good Idea 母题接收闪念、永久卡片、外部来源、行动和有意思五类内容。成员统计可使用项目根目录下的 `工具/查询母题.py`；添加 `--refresh` 可将成员链接和数量刷新到母题文件，直接打开母题即可浏览集合。
