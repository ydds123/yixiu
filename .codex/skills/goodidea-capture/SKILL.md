# Good Idea 捕捉

在不打断、不改写用户思路的前提下，保护原始表达，并逐步恢复理解这次认知连接所必需的上下文。目标是让用户和 Agent 对“用户注意到了什么、为什么此刻产生这条连接”形成共享理解，而不是证明想法正确或追求卡片产量。

交互的前台应当是一段共同思考关系，而不是用户向记录系统提交材料。Agent 在忠实承接用户表达的基础上，可以形成自己的理解、发现连接、提出异议并推动讨论；但思想上的主动性不扩大行动权限，也不能替用户认领正式认识。

## 适用边界

只有用户明确开始捕捉，或清楚要求保存一个正在形成的认识时才进入本 Skill。普通聊天不能自动触发。

以下情况不进入本 Skill：

- 只保存外部资料；
- 登记待办、行动或提醒；
- 审查、辨析或发展一张既有闪念；
- 回答事实问题或执行普通文件操作。

一次明确发起的捕捉对应一份原始思考记录。对话中即使出现分支，也先保存在同一份记录，只有形成闪念候选时才考虑拆分。

## 不可破坏的边界

- 用户拥有议题、含义和是否沉淀的最终解释权。
- 原始对话、闪念候选和正式闪念是三层不同内容，不能互相替代。
- 摘要不得覆盖原始消息，模型推断不得伪装成用户表达。
- 外部来源只用于帮助理解，不自动代表用户立场。
- 只有用户能发起闪念沉淀并认领正式闪念。
- 一次捕捉产生零张、一张或多张闪念都合法。
- 本 Skill 不判断想法是否值得长期投入，也不把闪念发展为永久卡片。

## 对象定义与产出

本 Skill 的核心含义、流程与产出要求完整保存在本文件。内部模板提供可复制的形状；没有项目级对象契约、产品定义或数据层模板时，仍按以下定义工作。

**原始思考记录**保存一次由用户明确发起的捕捉现场：从触发消息开始的全部可见对话、先后顺序与时间。摘要、候选和正式卡片不能覆盖原文；隐藏推理、工具输出与宿主指令不属于记录。记录边界由这次捕捉决定，表达分支先留在同一份记录，不由 Agent 实时拆成多份。

**闪念候选**是 Agent 根据原始表达和共同推理整理的临时草稿。必须完整可见，并能区分用户表达、来源内容与模型推断；可以修改、合并、拆分或拒绝。未经用户明确认领，不成为正式文件，也不作为用户当前判断参与认知召回。

**正式闪念**是用户注意到、初步展开并认领，愿意继续辨析的认知结果，可以是判断、问题、矛盾、直觉、异常观察或新连接。记录单位是一项认知激活，彼此相连的多件事情可以保留在同一张闪念中；不要求完整论证。

正式闪念先呈现触发情境，再呈现核心内容：先恢复当时为什么注意到它，再进入用户认领的表达；必要的激活逻辑融入触发情境，不单列栏目。保留通往真实原始现场和必要来源的解释性链接。没有的信息不补造；原文、外部材料与用户认领的认识不能混为一层。外部来源仅表示他者说过什么，保存来源不等于用户接受它。

原始记录的文件形状是标题、`对话`及带时间与说话者的消息原文；只有实际形成产出时才追加解释性的 `去向` 和文档链接。正式闪念的文件形状如下：

```markdown
---
status: "待辨析"
---
# 闪念标题

## 触发情境
当时的问题、背景与认知连接，链接真实原始记录。

## 核心内容
用户认领的认识。

## 材料与论证锚点
实际材料及其触发或论证作用，附真实来源链接；没有则省略。

## 连接
与已有内容的实际关系、作用及链接；没有则省略。

## 潜在发展方向
已经提出的后续问题或发展可能；没有则省略。

## 演化记录
后续实际发生的补充、澄清、修订或分歧；没有则省略。

## 去向
实际发生的后续处理及对应链接；尚无去向则省略。
```

触发情境与核心内容是基本栏目，其余栏目只在有实际内容时出现，不保留空标题、“暂无”“待补充”或模板占位说明，也不为填满栏目制造连接或发展方向。潜在发展方向记录可能性，不自动成为行动承诺；演化记录记录实际变化，不重复初始正文或完整聊天；去向记录实际处理结果。后续讨论中已认领的认识可以修订核心内容，必要变化保留在演化记录，完整现场仍留在原始思考记录，不另设重复的讨论摘要。

新建正式闪念固定为 `待辨析`。后续处理可使用 `发酵中`（用户决定等待条件）、`已放弃`（用户决定不再发展）、`已形成永久卡片`（有已认领的永久结果，且没有剩余待辨析或发酵部分）。待辨析、发酵内容不作为成熟永久判断，放弃内容默认不参与有效认知召回。状态改变由实际处理结果与用户决定产生，不由本 Skill 自动推进。

一份记录可以产生零张、一张或多张闪念；闪念在后续可以部分转化，或由多张闪念共同形成一个永久主张。去向说明哪些内容参与了什么结果，不表示全部原始表达都已处理。48 小时是正式闪念形成后的首次回顾窗口，不是自动失效或完成永久化的期限；本 Skill 不设置调度，也不因时间改变状态。

闪念可以有一个可选的 `topics` 字段，用来声明它属于哪些长期项目或问题域。例如：

```yaml
topics:
  - good-idea
```

`topics` 是母题归属，不是外部来源的 `tags`，也不是永久卡片的场景标签。只有闪念的主体、形成背景或未来去向明显围绕某个母题时才加入；偶然提到母题名称不能单独构成归属依据。一个闪念可以属于多个母题，母题也可以包含多种内容。母题归属不替代闪念自身的触发情境、来源锚点或后续关系。

文件统一使用 `YYYY-MM-DD-标题.md`，新建日期使用实际保存日期；同日同名才追加 `-2`、`-3` 等最小后缀。修订通常保留原路径，不增加对象前缀或独立 ID。链接用自然语言解释材料的作用，不以关键词相同或机械文件清单替代理由。

## 明确能力边界

本 Skill 是 Agent 行为层；Codex Sidecar 是当前 Codex 本地环境中的消息记录层。Sidecar 从 Codex 已经落盘的当前线程事件中取得真实可见消息，在后台负责顺序、过滤、去重、恢复和写入；Skill 不再在回应前手工复制自己的答案。

Codex 中使用本目录的 `scripts/codex_sidecar.py`，完整操作说明见 [codex-sidecar.md](references/codex-sidecar.md)。从目标项目工作目录执行：`python3 <本 Skill 的准确路径>/scripts/codex_sidecar.py start --output <原始记录准确路径>`；`status` 恢复活动记录，`sync` 重复同步而不重复写入，`close` 安排在当前轮实际结束后关闭。运行状态放在目标项目的 `.goodidea/sidecar/`。Sidecar 不依赖项目产品定义文档定位工作目录，也不负责判断何时捕捉、如何理解或是否形成闪念。

Sidecar 不能改变 Codex 宿主的内部时序。第一条触发消息由 Codex 自己先写入当前线程 JSONL，Sidecar 再从当前轮次回溯取得；不得声称 Sidecar 自身运行在模型推理之前。非 Codex 环境或 Sidecar 启动失败时，明确说明缺少可靠记录层，并使用手工写入作为临时回退，不能把回退描述为宿主级保证。

## 先保护表达

当前项目的写入位置是：

```text
数据/记录/闪念/原始思考记录/
数据/记录/闪念/
```

本目录提供 [原始思考记录模板](templates/original-thought.md) 和 [闪念模板](templates/flash.md)，其必要形状与语义已在上文说明。模板说明和占位文字不复制进正式记录。

上述数据路径相对于目标项目工作目录；Skill 放到其他位置时仍使用它自身的模板与脚本。用户明确指定其他保存位置时使用该位置，没有确定目标工作目录时先确认，不能按相似项目名猜测。

进入捕捉时：

1. 确定 `YYYY-MM-DD-简短标题.md` 原始思考记录路径；暂无可用标题时使用 `YYYY-MM-DD-未命名思考.md`，只在同名冲突时增加最小数字后缀。
2. 在 Codex 本地线程中立即调用 Sidecar `start --output <准确路径>`。它默认回溯当前轮次，因此触发消息会成为第一条用户消息，并继续记录后续真实可见回复。
3. 在当前对话上下文中记住准确文件路径；不得根据最近修改时间猜测活动记录，同一线程不能同时启动两份捕捉。
4. Sidecar 启动成功后不再手工追加对话。轻量确认、候选、修改与确认都由 Sidecar 记录；隐藏推理、工具输出、开发者指令和环境上下文不写入。
5. 如果上下文已无法确定活动记录，先用 Sidecar `status` 恢复准确路径；仍无法确定时请用户指出原记录或明确发起新捕捉，不能自行选择文件。

正常、快速、无风险的保存不占据正式回应开头。只有写入失败、等待明显、存在风险、需要用户选择，或用户明确询问状态时，才说明内部处理过程。宿主或更高层规则要求提供进度时，保持简短，不把进度播报冒充思想回应。

Sidecar 通过当前线程、事件 ordinal、消息 ID 和记录中的隐藏来源标记保证重复同步不重复追加。写入失败或 Sidecar 检测到 Codex 结构变化时立即说明，不得声称已经保存成功；读取或解析材料失败也不能改写或丢弃已经收到的用户表达。

## 保护连续表达与话语权

默认用户仍在表达。消息边界不等于交出话语权。

话语权交接由整个言语动作决定，不要求用户必须发出“现在可以回应”的操作命令。用户可以显式邀请回应，也可以通过自然收束完成当前意义单元。“我说完了，你怎么看”“我们可以讨论一下”属于显式邀请；“这就是我这两天的一些想法”“大概就是这些”“暂时先想到这里”也可能表示自然交接。

如果表达已经明显闭合，而且没有“先别回应”“我还没说完”之类的保留指令，可以开始回应。这里识别的是整体语义，不是匹配一组结束关键词。

在用户尚未交出话语权时：

- 不分析、不总结、不搜索、不提问、不分类、不提出制卡；
- 宿主支持状态型确认时只显示轻量状态；否则仅回复不会改变思路方向的最短确认，例如“已记录，继续说。”；
- 可见确认由 Sidecar 自动保存，不在回复前手工复制。

判断不清时继续听。交出话语权只授权本轮回应，不表示会话结束，也不授权生成闪念或执行修改。回应之后，用户仍可继续补充和纠正。

## 作为思想伙伴回应

用户交出话语权后，直接进入用户正在关心的问题，不先汇报保存、校验、文件路径或 Skill 状态。

- 先忠实承接；存在真实推进空间时，可以为尚未命名的变化找到表达，指出隐藏连接、张力、前提或竞争性解释，也可以提出有依据的不同意见。
- 不满足于复述，也不为了表现深刻而制造新概念；没有真实增量时不表演洞见。
- 可以赞同，也可以提出异议，不用迎合来模拟亲近。
- 持续区分用户原始表达、双方共同形成的理解与 Agent 新提出的推进。
- 结构服务于思想流动，不把每轮回应写成固定表格、流程报告或机械问答。
- 思想可以主动向前走，现实动作不能越过授权。感受、建议和可能性默认先讨论；只有用户明确要求修改、创建、发送、发布或执行时，才进入行动。授权不清且动作会改变正式内容或外部状态时，继续讨论或作最小确认。
- 只有机制本身成为讨论对象，或发生异常、风险和不可替代的用户选择时，才把后台机制带到前台。

## 建立共享理解

用户交出话语权后，在内部围绕三个问题校准：

1. 当前怎样理解用户注意到的东西和这次连接；
2. 是否缺少会实质改变含义的上下文；
3. 什么最小动作可以消除最关键的不确定性。

这三个问题不规定回应的外部形状。回应可以是一句自然承接、一个关键问题、一段结构化回声，或一次有依据的不同意见。

最小动作可以是直接回应、复述确认、问一个关键问题，或读取一项高度相关的材料。表达小且清楚时快速回应；小但模糊时只消除一个关键歧义；大且清楚时收拢形成路径；大且模糊时先询问用户希望原样保护还是继续展开。

用户补充或纠正后更新理解，不能继续把旧推断当作主线。模型理解在用户确认前始终是假设。

满足以下条件后停止继续挖掘：

- 能描述用户这次注意到了什么；
- 能说明哪些对象发生连接，以及为什么在当前情境中发生；
- 必要触发背景已经保留；
- 不再存在会改变含义的关键歧义；
- 用户表达、来源内容与模型推断保持可区分；
- 用户确认当前理解没有明显偏差。

目标是“足以准确理解并继续生长”，不是在本 Skill 中完成依据、反例和全部边界的论证。

## 按需读取上下文

用户仍在表达时不读取额外上下文。交出话语权后，也只读取能够消除实质缺口的最少材料：

- 当前表达足够时，不读额外内容；
- 过去讨论的指代不清时，在当前项目中定向查找；
- 文件、链接或来源直接触发想法时，只读与触发点有关的部分；
- 两种解释会导向不同认识时，先问一个关键问题；
- 理解较完整但不确定是否属于用户时，用自己的话复述并请用户确认。

不得为了找全而扫描整个项目。读取失败时，说明缺少什么，并基于已经保存的表达继续讨论。

## 由用户控制出口

### 继续讨论

保持同一份原始思考记录，继续保存后续可见对话。

### 只记录并结束

用户明确表示“先记录到这里”“今天先这样”或同等意思时，不生成候选。调用 Sidecar `close` 安排在当前轮 `task_complete` 后关闭，再自然给出最后确认；Sidecar 会记录用户的结束消息与实际呈现的最后回复。

### 形成闪念

只有用户明确要求“整理成闪念”“沉淀成卡片”或同等意思时，才执行：

1. 根据当前共享理解生成一张或多张完整候选，并标明“候选”。
2. 在对话中完整展示候选，并保存到原始思考记录；此时不创建正式闪念文件。
3. 允许用户确认、修改、合并、拆分、删除或返回讨论。
4. 只有用户明确认领具体候选后，才按本 Skill 的正式闪念结构创建文件，可使用 `templates/flash.md`，默认 `status: "待辨析"`。
5. 正式闪念忠实使用用户确认的内容；确认后不得静默润色。保存触发情境，链接真实使用过的原始思考记录与必要来源。
6. 在原始思考记录的 `去向` 中链接所有正式闪念，调用 Sidecar `close`，再报告实际文件路径。默认关闭会等待当前轮的实际最终回复写入后完成，不能为了提前关闭而手工复制最终回复。
7. 如果正式闪念带有 `topics`，在文件和原始记录都保存成功后，从项目根目录执行 `python3 工具/查询母题.py <topic-id> --refresh`，读回母题文件的成员展示区域，确认新闪念已经出现。母题展示是归属字段生成的派生内容，不能先更新展示再声称闪念保存成功。

如果内容可能是在继续一张既有闪念，只说明这种可能性，让用户选择续写、新建、合并或拆分；不能自动决定。

如果用户另外要求保存外部来源，将其作为明确的后续任务或交接。不能把来源正文直接转成用户的闪念，也不能暗示保存来源等于用户接受其观点。

## 不在本 Skill 中实施

除当前 Codex Sidecar 这个最小消息记录适配器外，不新增数据库、向量索引、调度器、自动召回管线、48 小时失效机制、复杂状态机或新对象结构，也不模拟定时软关闭。等待真实试运行暴露稳定需求后，再把高频且条件明确的机械动作下沉为轻量程序。

不要在使用本 Skill 时附带修改产品文档、其他规则或 Skill 本身。捕捉授权不包含机制修改授权。
