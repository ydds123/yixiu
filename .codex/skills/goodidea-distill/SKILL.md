# Good Idea 辨析与发展

帮助用户从“值得注意的认识”走向“愿意暂时使用的主张”。主线是：**恢复现场 → 去向判断 → 资格判断 → 接入判断 → 完整候选 → 用户认领 → 保存核验**。每次可以停在保留闪念、发酵、保留未决或建议停止，不以生成永久笔记为默认终点。

## 一、职责与共同边界

用户主动选卡、明确要求发展旧认识，或在独立回顾任务呈现后决定开始处理，才进入本 Skill。回顾任务负责调度与呈现，本 Skill 处理用户开始后的辨析，不承担定时提醒或回顾窗口管理。

主要输入是用户已认领的闪念，必要时读取原始讨论、触发材料和相关旧卡片。用户明确要求形成长期主张或补充已有卡片时，按当前材料处理，不为形式完整补造闪念或来源。多张闪念可以共同参与形成，默认按用户指定对象处理，不擅自合并其他闪念或扩大任务。

- 闪念保存用户注意到并认领、愿意继续辨析的认识；永久笔记保存一个可独立理解、使用和质疑的阶段性主张。“永久”不表示永远正确。
- 原始讨论保留形成现场；候选是建议，正式笔记是用户认领的具体版本。它们不互相覆盖，外部材料和过去表达不自动成为用户当前立场。
- Agent 主动比较、提出异议、查找依据和连接；用户掌握价值排序、含义纠正、最终去向和认领。提炼与拆分要让用户理解并认可，不要求用户亲手完成所有操作。
- 讨论建议不等于写文件授权。只有用户认领或明确授权保存、修改、记录去向时才执行对应操作；认领不能证明主张真实，也不能代替质量检查。

## 二、恢复现场与去向判断

先读目标闪念及理解它所需的最少材料，恢复注意到什么、为什么在意、涉及哪些对象和已有哪些补充。按实际缺口读取原始讨论或少量旧卡片，核对其当前正文和适用条件。材料取得失败时说明缺口，受影响的判断保留未决，不补造来源或依据。

起草前辨析：**是否值得保留、现在是否值得加工、是否需要独立永久笔记**。围绕具体问题与可能使用情境，比较加工增量、误用风险，以及创建、验证、维护和审阅成本。向内理解、感受、研究和精神安顿也属于用途；低频不等于低价值。

沿“需要 → 找到 → 正确适用 → 理解 → 使用 → 改善结果”寻找最影响用途的薄弱环节。这是诊断框架，不为每项猜分数。内容值得关注，不自动意味着需要永久化；表达已经清楚，也不自动意味着值得另建节点。

据此提出本轮去向，由用户决定：

- **继续加工**：当前投入有实质增量，进入资格判断。
- **完善已有对象**：更适合补充、修订旧卡片或留在已有文档，说明目标与拟修改范围，再按相应对象加工。
- **保留闪念并结束**：原闪念已经足够，或独立成卡增量不足，说明理由，不为展示而补候选。
- **发酵或保留未决**：说明关键缺口及值得重新打开的条件；判断不足时不强迫收口。
- **放弃**：可以建议，但实际去向由用户决定并授权记录。

Agent 应能主动说“不建议现在永久化”。零候选是完整结果；停止加工不授权删除、放弃、改变状态或改写原闪念。加工中发现重复、表达损失、只有形式变化或成本不相称时，返回去向判断，不反复改写来凑出结果。

## 三、资格判断：同一组性质用于加工与核验

先识别当前材料中可独立发展的主张，明确检查对象，再起草。判断能够分别成立、使用或被推翻时考虑拆分；共同支撑同一主张的理由、例子、反例和条件保留在一起。用户可纠正划分，新材料也可以改变它。

以下五项既是加工目标，也是门禁依据。按最影响预期用途的缺口加工，结果写入自然正文；不把检查过程变成卡片栏目或固定问卷。

| 性质 | 加工与核验要求 |
|---|---|
| 独立性 | 不读原始讨论也能理解主张、理由和成立条件。解释必要概念、缩写和内部背景，用一句话收拢中心含义，但不把一句话当作全文限制 |
| 原子性 | 围绕一个可独立使用、质疑和修订的主张。检查是否需要拆分，避免把支持同一判断的材料机械拆开 |
| 用自己的话 | 经过理解与重述，具有真实表达或理解增量。保留有助于理解的第一人称、现场感与自然推进；不以摘抄、换词或套模板代替加工，不把模型改写当作用户已经内化 |
| 指向性 | 能说明真实形成来源、服务的问题与调用情境，按需提出与旧认识的关系线索。第三层继续完成必填的网络定位并确认关系 |
| 完整性 | 说明为什么暂时接受、依据支持到什么程度，以及必要的适用条件、反例、过时风险和未决之处。材料与论证深度足以支持预期用途，不追求穷尽 |

事实、个人观察、外部主张、价值取舍和工作假设保持可辨认。来源可信不自动证明推导结论，触发材料不冒充成立依据，用户赞同不提高客观可信度。依赖关键外部事实时做必要查证，依据不足时降低主张范围或保留未决；用依据和限制说明置信程度，不生成无根据的概率。

候选不能静默改变原闪念的对象、范围、因果方向或认知主体。共同推敲形成修正时，说明变化理由，作为待认领版本呈现；原始表达继续保留。用户纠正含义或补充材料后，复核受影响的判断。

门禁结果为：**通过、需要重写、需要重新检查拆分、发酵或保留闪念**。重写或拆分以仍值得加工为前提；模型判定不通过时说明具体缺口，接受用户纠正后重新核验。通过只表示第二层最低质量要求满足，尚需第三层完成关系与接入，才构成完整可认领候选。

价值、重复和独立增量在加工中持续复核。发现更适合已有对象时返回去向或调整接入方式，不因草稿已写好就创建节点。讨论、检索和查证允许往返，不强制逐项追问或重复请求继续。

## 四、接入判断与关系定位

检查应当新建独立笔记，还是补充、修订已有卡片。按需读取少量相关旧认识，比较差异、支持、限制和冲突，说明接入方式及其作用，不凭关键词相同制造关系。

**来源与关系承担不同任务：**来源记录生成关系，说明认识怎么形成；关系是必填的网络定位，说明它怎样参与现有知识网络，帮助用户与模型判断何时调用、与哪些认识共同使用。

- **语义关系**：说明与具体卡片的支持、限制、冲突、补充、修正或例证，采用“链接＋关系及作用说明”，交用户确认。
- **场景标签**：用真实问题、功能或启发方向提供调用入口，学科名称本身不能代替用途。
- **索引或研究主题**：已有入口确实相关时，说明这张笔记在一组认识中承担什么位置。不为制卡预建分类树或索引。

这些是定位的不同方式，不要求每张笔记列齐三个子栏目。没有合适旧卡片时，仍须写清回应的问题与调用情境，具体语义链接可以保留未决；不能省略关系或只写“暂无关联”。无法说明有意义的位置时继续辨析或保留未决，不把空栏目视为完成。来源链接不能替代网络定位。

关系发现可以提前发生。新连接动摇主张时返回加工，复核变化后的版本。涉及旧卡片正文或关系的修改，须纳入用户审阅范围，不能借新笔记的认领静默修改其他对象。

## 五、模板与篇幅

正式永久笔记使用 [permanent-card.md](templates/permanent-card.md)，包含四个有实质内容的部分：**核心观点、论据、来源、关系**。

核心观点、论据与来源构成认识本身。影响观点含义的条件进入核心观点，限制依据支持范围的条件进入论据；来源区分触发、依据、补充和修正。关系说明网络位置与参与方式，不机械填满子字段，不把完整辨析过程搬进笔记。生成前读取模板，正式文件不保留模板提示文字。

**篇幅参考只计算“核心观点＋论据”的正文合计，暂以 100～300 字为参考。**标题、栏目名、来源、关系和文件管理信息不计入；来源与关系不设字数限制，按真实追溯与定位需要表达。超出范围触发原子性与论证冗余检查，不自动拆分、截断或拒绝保存，也不为压缩篇幅删掉必要条件。“140 字上下较佳”尚待实际使用验证，不作为门禁标准。

## 六、完整候选、认领与保存

针对本轮对象，集中呈现全部通过质量检查且完成网络定位的候选、拟议旧卡片修改和来源各部分的去向。未通过的内容单独说明缺口及去向，不与可保存候选混在一起；部分形成不等于整张闪念处理完成。用户可整体确认、逐项修改、拒绝或返回讨论，不人为增加确认轮次。

认领前复核四部分是否有实质内容，来源和关系是否真实，拟修改范围是否清楚。无待保存结果时结束本轮；用户仅要求讨论时不创建文件。修改后的候选按受影响的要求复核，用户认领的是具体版本，不沿用已被实质修改版本的旧确认。

认领后按当前本地约定执行：

1. 重新读取将要修改的文件，核对是否有新变化，并保留可恢复的原内容。
2. 保存已认领的具体版本。新建默认路径为 `数据/记录/永久卡片/YYYY-MM-DD-标题.md`，日期为实际保存日期；修改已有卡片通常保留路径。
3. 只更新用户已确认的关系和来源闪念去向。保留原始讨论与闪念正文，注明哪些部分形成了什么，哪些部分仍未决；反向可达通过现有反链或已审阅的必要回链实现。
4. 读回正文、来源目标、关系及实际去向，核对与认领版本一致。失败时区分已完成和未完成部分，重试前先核对，不把失败写成成功。

现有母题归属通过可选 `topics` 字段保存；仅在确有真实归属并纳入审阅时填写。它不代替关系说明。保存带有该字段的内容后，从项目根目录执行 `python3 工具/查询母题.py <topic-id> --refresh`，核对派生成员展示；失败时说明母题展示未完成，不把刷新当作认知内容已经正确的证明。

这些目录与母题刷新是本地约定，不作为通用产品契约。旧笔记保持历史结构，不自动批量迁移；重新整理时也须让用户审阅具体改动。
